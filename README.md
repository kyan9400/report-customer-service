# report-customer-service

Тестовое задание: небольшой REST-сервис на Node.js + Express + TypeScript, который отдаёт список записей с постраничной выдачей (пагинацией) через эндпоинт `GET /api/data`.

## Стек

- Node.js (LTS) и npm
- Express 4
- TypeScript 5
- ts-node-dev — запуск в режиме разработки с автоперезапуском

## Структура проекта

```
src/
  app.ts                   точка входа: создаёт Express-приложение, подключает JSON-парсер и роуты под /api
  routes/reportRoutes.ts   маршрут GET /data, читает page и limit из query-строки
  data/dataProvider.ts     источник данных (массив в памяти) и функция getData(page, limit)
```

## Запуск

```bash
npm install
npm run dev        # режим разработки (ts-node-dev, автоперезапуск при изменении файлов)
```

Сборка и запуск скомпилированной версии:

```bash
npm run build      # компиляция TypeScript в dist/
npm start          # node dist/app.js
```

Сервер слушает порт из переменной окружения `PORT` (по умолчанию `3000`).

## Переменные окружения

| Переменная | Назначение        | По умолчанию |
|------------|-------------------|--------------|
| `PORT`     | Порт HTTP-сервера | `3000`       |

Файл `.env` не используется — переменная читается напрямую из окружения процесса.

## API

### `GET /api/data`

Возвращает одну страницу записей.

| Query-параметр | Тип    | По умолчанию | Описание                        |
|----------------|--------|--------------|---------------------------------|
| `page`         | number | `1`          | Номер страницы (нумерация с 1)  |
| `limit`        | number | `10`         | Количество записей на странице  |

Пример запроса:

```bash
curl "http://localhost:3000/api/data?page=1&limit=1"
```

Ответ:

```json
[{ "id": 1, "name": "John Doe", "age": 30 }]
```

Некорректные или отсутствующие значения `page` и `limit` заменяются значениями по умолчанию. Данные хранятся в памяти (`src/data/dataProvider.ts`); база данных и внешние источники не используются.
